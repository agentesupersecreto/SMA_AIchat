Chat / Dialogue Personality Scoring

How the player's chat choices — the radial-wheel intro options "Say Hello" and "You Look" — are scored against a model's personality, what each existing choice does, and where the money stat lives. Reference for manipulating existing stats through chat: the whole chain (wheel wedge → conversation → stat change) already exists; this maps the scoring so new or edited choices tune predictably. Also covers the related model-trait gate: agency acceptance (§11–12). Code paths under SMANew/ExportedProject/Assets/Scripts/ unless noted.

1How "responds well" works

Each player choice carries a response-style tag + a weight (0–100), e.g. {pedante=75}. The model scores it against her taste for that style (gustoPor…, muyBajo→muyAlto). Taste sets an acceptance ceiling; the choice's weight is tested against it. Weight under the ceiling = good fit → +favorability (concentToHero). Weight over the ceiling = bad fit → +anger (rabia) and a negative return.
Model's taste for the style (gustoPor…)Acceptance ceiling
muyAlto loves it100

Submissive models (sumicion) get a widened interval, and high arousal multiplies it (the 4th argument table) — so aroused / submissive models tolerate bolder lines before they flip to anger.

2Scoring flow

The returned TipoDeRespuestaPuntaje… value drives the follow-up node via its conditionsString (e.g. Variable["TipoDeRespuestaPuntaje_HOLA_laCorrecta"]>=0), alongside the model's dominant personality MAYOR_PERSONALIDAD_* (set by MaxTipoDePersonalidad(...)).

3The scoring function

Each scored choice runs this in its node userScript:

Variable["TipoDeRespuestaPuntaje_…"] = CambiarEmocionAutoGestuadaPorTipoDeRespuestaLerp(
    Variable["ConversantID"],
    {pedante=75},        -- 1) response STYLE + weight (0–100)
    {concentToHero=10},  -- 2) emotions gained on a GOOD fit  (favorability)
    {rabia=40},          -- 3) emotions gained on OVERFLOW    (anger, bad fit)
    {arousal=2});        -- 4) tolerance widener (scaled by current arousal)

C# entry: RegistroDeFuncionesDeAI.CambiarEmocionAutoGestuadaPorTipoDeRespuestaLerp — fixed 4 tables, not varargs. Scoring is done in Personalidad.CalcularModificadorDeRespuestaV2, which maps the style to a gustoPor… taste trait, derives the ceiling from that trait's score, and tests the weight in UmbralBasico.Calcular.

ArgumentRole
idThe conversant (model) GUID — Variable["ConversantID"].
1 style table One or more {style=weight} entries. Each is scored, then averaged. The keys are the TipoDeRespuestaDeDialogoDePlayer enum (see §5).
2 gain-on-fit Emotions added when the style fits the model's taste, scaled by the good-fit modifier. Always concentToHero (favorability) in shipped content.
3 gain-on-overflow Emotions added when the weight overshoots the ceiling, scaled by the overflow modifier. Always rabia (anger) in shipped content.
4 tolerance bonus Widens the acceptance interval as a function of a live emotion (always arousal): an aroused model tolerates bolder lines before they overflow.

Return value: positive = good fit (favorability applied); negative (0 − overFlowMod) = overflow (anger applied).

4Weight = boldness / risk

The weight isn't just "intensity" — it's how demanding the model's taste must be before the line lands. A weight above her ceiling for that style overflows into anger.

Choice weightLands well withBackfires on
~15 mildalmost everyone (neutral and up) only models who actively hate that style
~50 mediummodels who like the style (alto+) neutral and averse models
~75 boldonly models who crave it (muyAlto) everyone else, mildly
~90–100 extremeonly muyAlto, and only if aroused / submissive nearly everyone, hard

8The money stat (Wallet)

Money is the SimpleWallet component, which lives on a GameObject literally named Wallet — present in each interview / meeting scene (Office0–4 Interview and …Meeting, plus EntrevistaSingleMode). It is not in OfficePlayerGamePlayLogic.

Inspector fieldTypeMeaning
m_walletStringKeyFloatValueDictionary Balances keyed by character/wallet GUID. Ships empty (keys: [] values: []).
m_historialList<CharacterWallet.Transacion>Transaction log.
You can't meaningfully type a balance in the inspector: m_wallet is a runtime-GUID-keyed dictionary that starts empty. Balances are created / changed at runtime via SimpleWallet.Change(id, value, sender), driven by the dialogue command SequencerCommandInputMoneyModalWindow (the "enter amount" popup) and the tipping / bribery flows. The Wallet object is where the stat lives; the value is populated by code / dialogue.
GOTCHA The MaleMoneySetter component on the Male Avatar / Female Avatar prefabs sounds like it sets money but does not touch the wallet. It sets perceived wealth — modifiers from outfit quality (sumadorDePorcentageOutfit) and office level (sumadorDePorcentageUbicacion) that feed how rich the model thinks you are (the lujosa / gustoPorDinero attraction). Different stat entirely.

9Authoring new choices

A new chat choice that moves existing stats is content only — no C# in the happy path:

  • Author a node in the PixelCrushers Dialogue Editor (select 0_Testing.asset), or edit the YAML directly.
  • In its userScript, call CambiarEmocionAutoGestuadaPorTipoDeRespuestaLerp(Variable["ConversantID"], {style=weight}, {concentToHero=…}, {rabia=…}, {arousal=…}) — or, for an unscored direct change, CambiarEmocionDeConversante("placer", 10).
  • Add the wedge: a GenericOpcionDeTHSDonaQueIniciaDialogo under the NPC's LoaderDeTHSDona, with m_conversation = your conversation name. Optional …IsGrayOut checker sibling to gate it.

Levers: style tag = which archetype it flatters (who responds well); weight = how demanding the model's taste must be (boldness / risk); concentToHero = reward on a good fit; rabia = penalty on a bad fit (scale both with boldness). For a lingering favorability bonus rather than an instant bump, use the Efecto / BuffDeCharacter route instead.

11Agency acceptance — how it works

Each agency is a ScriptableObject (Agencia) with a list of requirements and anti-requirements. A model is accepted only if she matches every requirement AND zero anti-requirements. Bonuses / anti-bonuses only adjust the income — they don't gate acceptance.

Verified from AgenciasHelper.RequerimientoCumplido:

  • Each requirement is exact set-membership, not a ≥/≤ threshold. "Body Fat low/very-low" rejects a medium model.
  • All traits read off the model's genetics interpretation (the same data shown in her profile panel).
  • No level / fame / age / money requirement exists — it's purely body, ethnicity, and personality.
  • Separately, every agency starts locked and is unlocked by buff / milestone effects, and there's a model willingness / consent gate. Those are independent of the per-model requirements below.
"≥ some" for descent means the model has at least some of that ethnic ancestry. The genetics scale is: very little → little → some → a lot → too much.
