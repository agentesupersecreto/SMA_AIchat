Model Hiring Cost System — Architecture

What decides how much money a model requires — her weekly salary and her commission % — when you hire and negotiate with her. The short version: it is a pure function of her personality traits (greed, poverty, modeling-willingness, intelligence). Her looks/rating, and everything about the player, are irrelevant to the number. All paths under SMANew/ExportedProject/Assets/Scripts/ unless noted.

1The big idea

A model's required money is decided entirely by her personality traits. Two numbers are negotiated at hire — a weekly salary and a commission % (her cut of each job). Both run through the same formula on the same trait inputs; only the output band differs. Greedy + not-poor → expensive; poor + low-greed → cheap. Nothing about the player (stats, charisma, karma, favorability) lowers the number — you can only haggle down to a floor, or overpay to buy favorability.

2The inputs (traits & scale)

Every input is a discrete personality trait on her Personalidad component (TraitHumano enum, scored by the 5-level HumanTraitScore enum). There is no continuous "avaricia" stat — greed = gustoPorDinero ("Taste for Money"); the method name "PobrezaYAvaricia" just means "poverty & greed".

3Desired salary formula

FemaleCharacterModelo.cs:101–115 — GetDesiredSalaryByPobrezaYAvaricia():

num   = 1 − weight(pobreza)                          // poorer → smaller
t     = num·0.25 + weight(gustoPorDinero)·0.75       // greed dominates
base  = Lerp(100, 1000, t)                           // ── base salary band 100–1000

t2    = weight(modelaje)·0.2 + weight(underwear)·0.3 + weight(herotico)·0.5
base2 = LerpConMedio(base·0.9, base, base·1.1, t2)   // modeling taste: ±10%

base3 = Lerp(base2·0.9, base2·1.0909, weight(inteligencia))   // intel: −10%…+9%
return Round(base3 / 5) · 5                           // snap to nearest 5
  • Base band 100–1000, set 75% by greed and 25% by (low) poverty.
  • Modeling-willingness nudges ±10% — note higher willingness asks slightly more (per the code).
  • Intelligence nudges −10% to +9%. Final rounded to the nearest 5.
  • Effective range ≈ 80 → ~1200. This is a weekly salary (§7).
Alternate variants GetDesiredSalaryByGustosModelaje() / …ComisionByGustosModelaje() exist (weight modeling tastes first), but the hiring dialogue uses only the …ByPobrezaYAvaricia() versions.

4Desired commission formula

FemaleCharacterModelo.cs:85–99 — GetDesiredComisionByPobrezaYAvaricia() is structurally identical to salary, only the bands change:

t     = (1 − weight(pobreza))·0.25 + weight(gustoPorDinero)·0.75
base  = Lerp(30, 80, t)                              // ── base commission 30–80%
base2 = LerpConMedio(base·0.875, base, base·1.0625, t2)        // taste:  ±~6–12.5%
base3 = Lerp(base2·0.875, base2·1.0588, weight(inteligencia))  // intel:  −12.5%/+5.9%
return RoundToInt(base3)                              // integer percent

Commission is her percentage cut of each job's gross income. Effective range ≈ 23% → ~89%.

5Negotiation — the 80% floor

Negotiation runs through Lua dialogue functions in DialogueSys/Trabajos/RegistroDeFuncionesDeContratacionDeModelos.cs. Variables: SALARIO_OFERTA (your offer), SALARIO_CONTRA_OFERTA (her counter), SALARIO_RESULT (agreed) and the COMISION_* equivalents.

GetSalaryOfferAceptanceW() (~248–278) computes ratio = offer / desired:

  • offer ≥ 0.8 × desired → accepted, no counter.
  • Below that she counters: the first counter is an inflated desired × 2 anchor; subsequent counters interpolate down toward 0.8 × desired on a squared curve.
  • Commission haggling (GetComisionOfferAceptanceW(), ~215–246) uses the same 0.8 threshold.
You can haggle, but only down to 80% of her desired figure. Nothing the player has — charisma, karma, favorability, stats — moves the desired number itself.

6Overpaying buys favorability

The only player-facing lever runs the opposite direction from haggling — paying more than she wants grants her a favorability buff toward the player:

8Where the traits come from

The cost inputs split into two provenances:

  • Generated from genetics: gustoPorDinero and the three modeling tastes are produced by the gusto interpreters — InterpretadorDeGustos.cs:62 (result.gustoPorDinero = …GetParaGenesPorValor(helperTraits.gustoPorDineroValorPolarizado)), schema in InterpretacionDeGustos.cs:428–440 ("Taste for Money"). So a model's greed and willingness ride along with the genetic pool that the rating system breeds.
  • Authored directly in personality-map assets: pobreza and inteligencia are not produced by the interpreters — they are written as Trait entries in the personality maps (e.g. Assets/MonoBehaviour/PersonalidadFemenina_DEFECTO.asset, MapaRamModFem_HumanTraits.asset). Absent → defaults to normal (0.5).

All traits are stored on Personalidad as a serialized List<Trait> (Trait { TraitHumano trait; HumanTraitScore score; }), read via GetTraitScore() / written via SetTraitScore(). FemaleCharacterModelo grabs the component in AwakeUnityEvent() (GetComponentEnRoot<Personalidad>()).
