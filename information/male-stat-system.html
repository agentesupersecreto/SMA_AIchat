Male Stat System — Architecture

How the playable male character's stats are stored, derived, and displayed — the layered "alterador" body-stat model, the derived Curriculum metrics (height / weight / bodyfat / age / length / girth), and the eight buff/debuff categories. Surfaced in-game by the "My Info" / Playable Character Info panel. All paths are under SMANew/ExportedProject/Assets/Scripts/ unless noted.

1Two stat families

The male character has two distinct kinds of "stat", surfaced as tabs in the same panel:

  • BODY / CV  Static body attributes — name, age, sex, height, weight, bodyfat, and genital length/girth. These are derived on demand from the character's alteradores (the body sliders set in character creation) and the Penis component. Shown on the Curriculum tab.
  • BUFFS  Dynamic buff/debuff stacks across 8 categories (favorability, pleasure, desires, rage, pain, fear, decep, other). These are live, time-limited gameplay effects read from the character's BuffDeCharacter registry. One tab each.
The body metrics are computed every time the panel draws (no cached "stat sheet") — they are pure functions of the alterador values plus a couple of body-measurement components.

3The alterador stat primitive

Every tunable body stat is an AlteradoresDeCharacterMasculino.ValorFlotante — a three-layer value, not a plain float. This is the core stat pattern:

public float valorMidifcado => modificable.ModificarValor( addicionable.AdicinarValorIncluyendo( @base ) );
//                              └ multiplicative ─┘ └ additive ──────────┘ └ base ┘
LayerTypeRole
@base (m_base)serialized float The authored/creation value (e.g. set by a character-creation slider, LoadBase()).
addicionableModificableDeFloat(0) Additive contributors stacked on top of base (flat bonuses).
modificableModificableDeFloat(1) Multiplicative modifiers applied last (scaling factors).

The holder, AlteradoresDeCharacterMasculino, extends HolderTrialDeAlteradores<…> and exposes each stat as an alteradorDe<X>Valor property over its backing ValorFlotante. It ticks on GlobalUpdater.UpdateType.update2. The Modificable* wrappers are the same modifier-stack mechanism used across the game (the [SerializeReference] modifier fields AssetRipper drops are rebuilt at runtime).

Per-buff row

For each DisplayableBuff in the category (excluding hideFromUI), the row shows:

  • Text — buff.LocalizedText() (model name stripped out).
  • Time remaining — "Permanent" if EndDateTime.Year ≥ DateTime.MaxValue.Year, else a localized countdown (years/weeks/days/hours/minutes) vs TiempoDeJuego.now.
  • Color — buff.quality.GetColor() (quality band).
  • Tooltip — optional IDisplayableCustomToolTip.tooltip.

Rows are ordered by displayFirst ↓, then distance of quality from 7 ↓, then priority ↓ — so pinned and extreme-quality effects surface first.

REBUILD AssetRipper stripped the entire BuffDeCharacter body (it derives from a generic base, EventosUnicosLocales<…>), dropping its [SerializeField] m_memoriaPermanenteTarget → that ref is null at runtime → AwakeUnityEvent threw ArgumentNullException: m_memoriaPermanente on every character spawn → the per-character buff registry never started, so buff-driven stats silently did nothing — most visibly the favorability-by-attraction aura, so the favorability bar didn't rise during a meeting (attraction itself computed fine). Fixed by a runtime self-heal in AwakeUnityEvent: when the ref is null it re-resolves to the character's MemoriaDeIntereaccionesDeCharacter (the only permanente memory on the root), verified against the shipped IL. This restores the buff/debuff system game-wide. (This throw was previously believed benign — it was not.) See SMANew/REBUILD_DEVIATIONS.md.

7Where it's shown

The stats render in the "Playable Character Info" panel (the female equivalent is "Talent Development"), opened from the office PC start-working panel via the My Info button (PanelComenzarATrabajar.ShowMyInfo). It is one of the diegetic floating world-space panels anchored to the character's head bone.

For the panel/show plumbing — and the two AssetRipper defects that left "My Info" dead (a draw-order crash and a stripped enableCanvasOnShow flag) — see floating-panels-and-male-stats.html.
