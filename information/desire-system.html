Desire System — Architecture

How a female model's four desires (mouth, breast, crotch, ass) are stored, raised by stimulation, and bounded by a dynamic ceiling — including how that ceiling is improved over a session ("trained capacity") and suppressed by fatigue. This is the value that the diegetic desire bars (BarraDeDeseo*) read, and the gate the reactors check before teasing / sex. All paths are under SMANew/ExportedProject/Assets/Scripts/ unless noted.

1The four desires

The Deseos component tracks four independent desires, one per erogenous zone. Each is a signed percentage and has its own current value and its own dynamic ceiling:

A genital / testicle / inverted "package" stimulus raises all four at once, each scaled by its own growth unit. The same enum, Desires (All · None · Crotch · Ass · Breast · Mouth), is how buffs address a single desire.

2The value model — current vs ceiling

Each desire's displayed percentage is produced on demand by one function, Valores.GetDeseoPercentage(...) (…/CuchiCuchi/AI/Deseos.cs). It is recomputed once per ForcedUpdateId tick and cached:

// current value = (additive layer) then (multiplicative layer), clamped to [-100, ceiling]
float ceiling = maxValoresSumador.AdicinarValorIncluyendo( maximoInicial + maximoValorAdded ); // additive
      ceiling = maxValoresModificador.ModificarValor( ceiling );                                // multiplicative
return Mathf.Clamp( modificador.ModificarValor( sumador.AdicinarValorIncluyendo( valorInicial + valorAdded ) ),
                    -100f, ceiling );

4How a desire is raised (the gain rate)

Every stimulus routed through RegistrarEstimulo(...) resolves the touched body part to one of the four desires + a tier (primary / secondary / tertiary) and calls the matching AumentarDeseo<Zone>(amount). The amount is a product:

amount = unidadDeAumento · 100 · Time.deltaTime
         · deseoGanancia<Primario|Segundario|Terciario>   // body-zone tier weight (trait-scored)
         · ModPorEmocion(calculo)                            // pleasure / pain / rage / other × pos|neg trait
         · ModPorTipoDeInteraccion(calculo)                  // visual / verbal / tactile / exposure / coital sensitivity

Then inside AumentarDeseo* it is scaled once more by the per-girl gain (m_modificablesGains.X.ModificarValor(initialAumentoMods.X)) before being banked:

m_addingValores.X    += amount · gain;             // raises the CURRENT desire
m_addingMaxValores.X += amount · gain · 0.05;      // raises the CEILING by 5% of the same gain
The ModPorEmocion sign matters: a negative emotion (pain / rage) with a low deseoGananciaPorEstimulosNegativos trait yields a negative amount — the same stimulus that would build desire on a willing girl actively drains it (and lowers her ceiling) on an unwilling one. Pleasure uses modPorPlacer = 1.0; pain 0.75; rage 0.5; other emotions 0.25.

5How the ceiling is improved

The interesting term is m_addingMaxValores — the "trained capacity". It is what makes repeated play permanently raise how high a desire can climb, and it moves through three paths:

  • BANKING  5 % of every desire gain is added to the ceiling (the · 0.05 above). The more a zone is stimulated, the higher its ceiling drifts — clamped to ±500. This is the core "practice raises your capacity" mechanic.
  • ORGASM SURVIVES  On orgasm the system subtracts a resilience amount from m_addingValores (the current desire drops — a refractory reset) but does not touch m_addingMaxValores. So each climax resets the level while leaving the raised ceiling in place — that is the within-session progression.
  • BUFFS  The additive / multiplicative max-buff layers (§7) move the ceiling temporarily without touching the banked value.

The orgasm drop is itself trait-scored (deseosResiliance): a higher resilience means a bigger post-orgasm desire reset.

7Buffs that move the ceiling

BuffOnDeseoGainAndMaxValueEffecto applies a single buff that sets both the gain multiplier (modificablesGains.X) and the additive-max modifier (valoresMaximosSumablePercentage.X) to the same mod value, keyed on the buff's id and addressed by the Desires enum. On Remove both modifiers are pulled back off.

The one shipped user is DeseosGainMaxByFatigue: when a girl is tired it lerps that mod 1.0 → 0.2 by her stored fatigue (Mathf.Lerp(1f, 0.2f, applyableFatigueMod)) for every desire, for a 3-hour duration. So fatigue simultaneously throttles her gain rate and caps how high desire can reach; rest restores it. The buff also drives a quality band (ItemQuality) for the UI from mod × stacks.

Both layers are ModificableDeFloat modifier stacks — the same [SerializeReference] modifier mechanism used across the game, rebuilt at runtime (the stripped modifier lists are not load-bearing; see memory: serializereference-non-loadbearing).
